evidencestore is an independent witness for logs. A collector next to the log sends every line to a store on another machine, and the store can later prove any of those lines to an auditor, offline and without being trusted: the exact bytes, their place in a hash chain, a signed chain head and RFC 3161 time-stamps from before and after the record. Retention works by destroying a month's key: the bodies become unreadable in every copy, while the chain and the proofs stay valid.

This release fixes two defects of the Docker installation that are in v0.7.0. The store, the collector and `esverify` are those of v0.7.0.

## Fixed

These defects are in v0.7.0.

- **`tar` warned about files "in the future" when a collector's bundle was unpacked.** The files of the bundle carried the store's current time, with fractions of a second, and a collector's host whose clock is a little behind saw them as made later than now. The collector worked all the same. The files now carry a time an hour earlier, in whole seconds, the same margin as the certificates.
- **The store in Docker and the PostgreSQL trial were one compose project.** Both files named their project `evidencestore` and both have a service `store`, so on one host the second `docker compose up` would replace the first one's store container. The store's `compose.yaml` now names its project `evidencestore-store`.

## Upgrading

- A store in Docker from v0.7.0: download the `compose.yaml` of v0.7.1 over the old one, then `docker compose -p evidencestore down` once (the old project) and `docker compose up -d`. The config, the data and the keys stay in the directories next to the file. Collectors from v0.7.0 bundles work unchanged; their image can stay at v0.7.0.
- Anything else: nothing changes.

## Known issues

As in v0.7.0: certificates in Docker are not renewed (the collectors' for two years, the CA's for ten), a bundle reads one log, and the backup of the keys and the roots mirror default to directories next to `compose.yaml`. All of them: [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.1/docs/limitations.md).

## Install

In Docker, on the store's host:

```sh
curl -fsSLO https://raw.githubusercontent.com/Nikolay1994Kaz/evidencestore/v0.7.1/deploy/docker/store/compose.yaml
ES_HOST=logs.example.com docker compose up -d
docker compose exec -T store add-collector web1 > web1.tgz
```

and on web1: `tar -xzf web1.tgz && cd web1 && docker compose up -d` ([In Docker](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.1/docs/install.md#in-docker)). Check the image: `gh attestation verify oci://ghcr.io/nikolay1994kaz/evidencestore:v0.7.1 --repo Nikolay1994Kaz/evidencestore`.

Binaries for Linux, `esverify` and `esreceipt` also for macOS and `esverify` for Windows, with `SHA256SUMS` and attestations, are on this page; on hosts with systemd: [README, Install](https://github.com/Nikolay1994Kaz/evidencestore#install).

## How it was tested

- The test gate with the race detector, and `scripts/docker-check.sh` on every push and on the published image of this release. A unit test now requires the bundle's files to carry a time in the past, in whole seconds.
- The PostgreSQL trial in Docker ran by hand for the first time: `docker compose up` from scratch, an agent's action through the MCP server undone with `esundo`, a change made past the server kept as a fingerprint, a statement the server refuses, and the agent's read-only connection refused a change ([PostgreSQL and an MCP server](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.1/docs/postgres.md#limits)).

## Before you use it

- Until 1.0 the on-disk formats (evidence log, chain, keyring) may change; each release will describe the way over.
- The pilot cryptography is not certified: AES-256-GCM from the Go standard library, root keys in files. The root store is a plug-in point for an HSM.
- Read [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations).
