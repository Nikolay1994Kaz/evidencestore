evidencestore is an independent witness for logs. A collector next to the log sends every line to a store on another machine, and the store can later prove any of those lines to an auditor, offline and without being trusted: the exact bytes, their place in a hash chain, a signed chain head and RFC 3161 time-stamps from before and after the record. Retention works by destroying a month's key: the bodies become unreadable in every copy, while the chain and the proofs stay valid.

This release installs the store and its collectors in Docker, with their certificates, from an image published with the release. Nothing else changed: the store, the collector and `esverify` work as in v0.6.0.

## New in this release

- **The store and its collectors in Docker, on their own hosts.** On the store's host:

  ```sh
  curl -fsSLO https://raw.githubusercontent.com/Nikolay1994Kaz/evidencestore/v0.7.0/deploy/docker/store/compose.yaml
  ES_HOST=logs.example.com docker compose up -d
  docker compose exec -T store add-collector web1 > web1.tgz
  ```

  and on web1, with `web1.tgz` copied there: `tar -xzf web1.tgz && cd web1 && docker compose up -d`. The first start makes a CA for the collectors, the server certificate for the names in `ES_HOST`, the config with DigiCert time-stamps (`ES_TSA=nca` for the NCA of Kazakhstan, `local` for a trial) and the keys. `add-collector` issues the collector's certificate, pins its fingerprint in the store's config, writes a bundle with the certificates, the collector's config and its compose file, and restarts the store's `serve` inside the container so it accepts the new source. The collector's private key exists only in the bundle. Operator commands find the config themselves: `docker compose exec store evidencestore status` ([In Docker](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.0/docs/install.md#in-docker)).
- **An image for every release.** `ghcr.io/nikolay1994kaz/evidencestore:v0.7.0` (and `:latest`), for linux/amd64 and linux/arm64, holds exactly the binaries of this release page, with an attestation of where it was built. Both containers run as root without capabilities and with a read-only root file system; the collector gets one capability, `DAC_READ_SEARCH`, to read the log and its key.
- `evidencestore docker init` and `evidencestore docker add-source` are the commands behind it, for those who build their own image.

## Compatibility

- Nothing changes for an existing installation: the data formats, the intake protocol and the configs are those of v0.6.0, and collectors of v0.6.0 work with this store.
- The Docker installation is new and separate from the PostgreSQL trial (`compose.yaml` in the repository root), which is unchanged.

## Known issues

- **Certificates in Docker are not renewed.** The collectors' certificates are valid for two years and the CA for ten, and no command renews them yet. The CA's key stays on the store's host; an organization with its own PKI installs on hosts instead ([Installing on hosts](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.0/docs/install.md)).
- **One log per bundle.** A collector from `add-collector` reads one file; several logs on a host are several bundles.
- **The backup of the keys and the roots mirror default to directories next to `compose.yaml`.** For anything beyond a trial, set `ES_BACKUP_DIR` and `ES_ROOTS_MIRROR_DIR` to other disks before the first start, and do not copy the whole directory somewhere: `roots/` must have no copy apart from its mirror.
- **The PostgreSQL trial in Docker has still not run under Docker**, as in v0.6.0.
- From earlier releases: the PostgreSQL path rests on its trust boundary; the seal on the store key checks RSA and ECDSA with SHA-2 only (no ГОСТ); cosignatures are Ed25519 only.

All of them, with their causes: [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.0/docs/limitations.md).

## Install

In Docker: above. Check the image:

```sh
gh attestation verify oci://ghcr.io/nikolay1994kaz/evidencestore:v0.7.0 --repo Nikolay1994Kaz/evidencestore
```

Binaries: `evidencestore`, `escollect`, `eswitness`, `esmcp` and `esundo` for Linux amd64 and arm64; `esverify` and `esreceipt` also for macOS (amd64, arm64), and `esverify` for Windows (amd64). Check them before use:

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify esverify-linux-amd64 --repo Nikolay1994Kaz/evidencestore
```

With Go 1.25.4 or newer: `go install github.com/Nikolay1994Kaz/evidencestore/cmd/esverify@v0.7.0`, likewise the other commands. On hosts with systemd: [README, Install](https://github.com/Nikolay1994Kaz/evidencestore#install).

## How it was tested

- The test gate with the race detector, on every push.
- `scripts/docker-check.sh` follows the Docker steps of the docs on one Docker host: the store from `compose.yaml`, a collector from its bundle as a separate project reaching the store by the host's address, a line of the log through to `esverify` (VERIFIED); `add-collector` refuses a name it has issued without changing the config; the collector's key is nowhere on the store's host. CI runs it on every push with an image built from source, and in the release on the published image before the release page is made.
- By hand, with real DigiCert time-stamps: the same steps through to VERIFIED; `docker compose stop` ends the store cleanly; the store's own `serve` restarts after `add-collector`.
- Unit tests of `docker init` and `docker add-source`; five bugs injected by hand into the new code each made them fail. The mutation sets and the simulations were not run again: the store, the collector and `esverify` are those of v0.6.0.

Details: [docs/testing.md](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.7.0/docs/testing.md).

## Before you use it

- Until 1.0 the on-disk formats (evidence log, chain, keyring) may change; each release will describe the way over.
- The pilot cryptography is not certified: AES-256-GCM from the Go standard library, root keys in files. The root store is a plug-in point for an HSM.
- Read [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations).
