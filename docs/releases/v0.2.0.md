evidencestore is an independent witness for logs. A collector next to the log sends every line to a store on another machine, and the store can later prove any of those lines to an auditor, offline and without being trusted: the exact bytes, their place in a hash chain, a signed chain head and RFC 3161 time-stamps from before and after the record. Retention works by destroying a month's key: the bodies become unreadable in every copy, while the chain and the proofs stay valid.

## New in this release

- **Witness of the chain heads.** Whoever holds the store's signing key can sign a second version of the chain. With `witness.url` (S3 or a directory) the store now sends its signed chain heads, and nothing else, to a witness run by someone that administrator does not control: the auditor, another organization, a cloud bucket with S3 Object Lock. `esverify -heads DIR` checks a bundle against the heads the auditor took from the witness: a chain rewritten after the witness saw a head, or two versions of the chain signed with the store key, no longer verify. `evidencestore proof -to-head N` extends a bundle to a witnessed head. The witness has its own S3 credentials (`ES_WITNESS_*`), and writes to S3 carry `Content-MD5`, which buckets with Object Lock require.
- **Proof bundles no longer grow with the chain.** A bundle used to carry every link up to the current head, about 173 bytes for each link written after the record: megabytes after a day of steady intake, gigabytes after a year. It now ends at the head under the time-stamp that covers the record, and the links are read as a stream instead of loading the whole chain file.
- **`esverify -body FILE`** writes the record body byte for byte once the bundle verifies, so the original log can be rebuilt from the store.
- **Output in English** from `esverify`, the chain errors and the demos.
- **`go install` works**: the module path is `github.com/Nikolay1994Kaz/evidencestore`.
- **A new demo**, `scripts/demo-intruder.sh`: an intruder cleans `auth.log`, and every deleted line comes back from the store, verified offline. The project is described in one long read: [docs/ARTICLE.md](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.2.0/docs/ARTICLE.md) ([in Russian](https://github.com/Nikolay1994Kaz/evidencestore/blob/v0.2.0/docs/ARTICLE.ru.md)).
- **What stands against the store's own administrator** is now stated in the README as it is: the time-stamps, and a witness that administrator does not control.

## Compatibility

- Proof bundles keep format version 1. Bundles from v0.1.1 verify with this `esverify`, and bundles from this store verify with the v0.1.1 `esverify` (which has no `-heads`).
- The on-disk formats (evidence log, chain, keyring) did not change. Upgrade by replacing the binaries: the store first, then the collectors.
- The `witness` section of the config is optional.

## Install

Binaries: `evidencestore` and `escollect` for Linux amd64 and arm64, `esverify` also for macOS (amd64, arm64) and Windows (amd64). Check them before use:

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify esverify-linux-amd64 --repo Nikolay1994Kaz/evidencestore
```

With Go 1.25 or newer: `go install github.com/Nikolay1994Kaz/evidencestore/cmd/esverify@v0.2.0`, likewise `cmd/evidencestore` and `cmd/escollect`.

Setting up a store and collectors, with systemd unit files: [README, Install](https://github.com/Nikolay1994Kaz/evidencestore#install).

## How it was tested

The test gate with the race detector, in CI on Go 1.25.4. Mutation testing: 316 injected bugs ran in full on 12 October (commit `957345c`), each caught by a test; every change since came with its own mutations, 22 in all, run against the code they guard and all caught. The witness and the copy were tried end to end on MinIO with Object Lock. Details: [README, How it was tested](https://github.com/Nikolay1994Kaz/evidencestore#how-it-was-tested).

## Before you use it

- Until 1.0 the on-disk formats (evidence log, chain, keyring) may change; each release will describe the way over.
- The pilot cryptography is not certified: AES-256-GCM from the Go standard library, root keys in files. The root store is a plug-in point for an HSM.
- Read [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations).
- There is no container image yet.
