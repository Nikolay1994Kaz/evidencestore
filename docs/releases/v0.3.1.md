v0.3.0 and one command for trying the store. `evidencestore dev-setup -dir DIR` prepares a demo store in a new or empty directory: a demo CA with certificates for the store and for the source, the store's config with time-stamps from the demo TSA built into the store, `init`, and the collector's config with the store's public key pinned in it. It starts nothing: `serve`, `escollect`, `stamp`, `proof` and `esverify` stay the commands you type ([README, Run it yourself](https://github.com/Nikolay1994Kaz/evidencestore#run-it-yourself)). The demo CA and the built-in TSA are for a try, not for real logs.

Also in this release:

- The copy's S3 credentials come only from `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. The old, never documented names `KVSTORE_S3_ACCESS_KEY` and `KVSTORE_S3_SECRET_KEY` are no longer read: if you set them, set the `AWS_` ones instead.
- The README says plainly that the two approvals a key destruction needs are names the chain records, not people the store authenticates ([Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations)).

Nothing else changed: intake, the chain and the proofs, the collector, `esverify`, the configuration and every on-disk and bundle format are those of v0.3.0, and data and bundles of v0.3.0 work as they are.

## Install

Binaries: `evidencestore` and `escollect` for Linux amd64 and arm64, `esverify` also for macOS (amd64, arm64) and Windows (amd64). Check them before use:

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify esverify-linux-amd64 --repo Nikolay1994Kaz/evidencestore
```

With Go 1.25.4 or newer: `go install github.com/Nikolay1994Kaz/evidencestore/cmd/evidencestore@v0.3.1`, likewise `cmd/escollect` and `cmd/esverify`.

Setting up a store and collectors, with systemd unit files: [README, Install](https://github.com/Nikolay1994Kaz/evidencestore#install).

## How it was tested

- The test gate with the race detector, in CI on Go 1.25.4.
- `dev-setup` has its own tests: both configs it writes pass the loaders of the store and of the collector, the key pinned in the collector's config is the store's own, a second run changes nothing, and a non-empty directory is left alone. Seven bugs injected into the command by hand were each caught by these tests. A test checks that the old `KVSTORE_S3_*` variables give no credentials.
- The section [Run it yourself](https://github.com/Nikolay1994Kaz/evidencestore#run-it-yourself) was run as written, through `dev-setup` and through the steps it replaces: both end with `VERIFIED`.
- Apart from `dev-setup` and the copy's credentials, the code is that of v0.3.0 and was tested for it: [v0.3.0](https://github.com/Nikolay1994Kaz/evidencestore/releases/tag/v0.3.0).

## Before you use it

- Until 1.0 the on-disk formats (evidence log, chain, keyring) may change; each release will describe the way over.
- The pilot cryptography is not certified: AES-256-GCM from the Go standard library, root keys in files. The root store is a plug-in point for an HSM.
- Read [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations).
- There is no container image yet.
