Same code as v0.1.0, rebuilt. In v0.1.0 eight of the nine binaries reported their version as `v0.1.0+dirty`: they were built from the tagged commit (their provenance attestation says so), but the build directory sat inside the source tree and made it look modified. The build directory is now ignored by git, and the release script refuses to publish a binary marked as built from a modified tree. Use this release.

evidencestore keeps audit records — actions of AI agents, logs of core banking systems, a copy of the SIEM stream — so that an auditor can check any record offline, without trusting the store: the exact bytes, their place in a hash chain, a signed chain head and RFC 3161 time-stamps from before and after the record. Retention works by destroying a month's key (two approvers, a waiting period): the bodies become unreadable in every copy, while the chain and the proofs stay valid.

## In this release

- `evidencestore` — the store: intake over mutual TLS, an `fsync`-before-"accepted" evidence log, a hash chain anchored by an external TSA, per-month keys with crypto-erasure, a copy to S3 or a directory with restore, Pipelock flight-recorder verification, Prometheus metrics.
- `escollect` — the collector: follows a log file or a glob of files through rotations, spools lines on disk, keeps the store's signed promises.
- `esverify` — the auditor's tool: verifies a proof bundle offline and says what is and is not proven.

## Install

Binaries: `evidencestore` and `escollect` for Linux amd64 and arm64, `esverify` also for macOS (amd64, arm64) and Windows (amd64). Check them before use:

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify esverify-linux-amd64 --repo Nikolay1994Kaz/evidencestore
```

Setting up a store and collectors, with systemd unit files: [README, Install](https://github.com/Nikolay1994Kaz/evidencestore#install).

## How it was tested

Test gate with the race detector; 316 injected bugs, each caught by a test; simulations — the store with crashes (2,000 scenarios of 300 steps), the receive-time clock (3,000), the collector (over 10,000 scenarios, part of them against the real store); the demo with a live Pipelock v3.6.0; a night on real data, where 104,738 records from the host's own logs and a live Pipelock matched their sources line by line and the store restored from its copy gave the same result. Details: [README, How it was tested](https://github.com/Nikolay1994Kaz/evidencestore#how-it-was-tested).

## Before you use it

- Until 1.0 the on-disk formats (evidence log, chain, keyring) may change; each release will describe the way over.
- The pilot cryptography is not certified: AES-256-GCM from the Go standard library, root keys in files. The root store is a plug-in point for an HSM.
- Read [Known limitations](https://github.com/Nikolay1994Kaz/evidencestore#known-limitations).
- There is no container image yet.
